**Status:** Designed. Code TBD.

---

## Hypothesis

A BUY signal generated by the model is more likely to be WRONG (i.e., the stock fails to rise) when both conditions hold:

1. The stock is within N days post-earnings (recent earnings report)
2. Institutional flow has been negative in prior 5 days (`inst_signed_flow_5d < threshold`)

Rationale:
- Post-earnings drift can be negative if earnings were soft or guidance disappointed
- Concurrent negative institutional flow is smart-money flagging a problem
- Together: model may be picking up technical bullishness while smart money is exiting

If hypothesis true → suppressing BUY in this regime improves precision (fewer false BUYs).

## Backtest design

### Step 1: Build the analysis dataset

Single SQL JOIN:

```sql
SELECT 
  p.ticker, p.prediction_date, p.horizon,
  p.signal, p.prob_eff,
  o.actual_return, o.actual_up,
  pf.inst_signed_flow_5d,
  (SELECT MAX(date(report_date))
   FROM earnings_surprises e 
   WHERE e.ticker = p.ticker
     AND date(e.report_date) <= date(p.prediction_date)
  ) AS last_earnings_date,
  julianday(p.prediction_date) - julianday(
    (SELECT MAX(date(report_date))
     FROM earnings_surprises e 
     WHERE e.ticker = p.ticker
       AND date(e.report_date) <= date(p.prediction_date)
    )
  ) AS days_since_earnings
FROM predictions p
JOIN outcomes o USING (ticker, prediction_date, horizon)
LEFT JOIN prediction_features pf USING (ticker, prediction_date, horizon)
WHERE p.signal = 'BUY';
```

### Step 2: Compute baseline metrics

Per horizon (h=1, 3, 5):
- N total BUYs
- hit rate (% with actual_up=1)
- avg actual_return
- precision = hit_rate (already same in binary classification)

### Step 3: Grid search the suppression rule

For each combination of:
- N_days_post_earnings ∈ {3, 5, 7, 10, 14}
- inst_flow_threshold ∈ {-0.05, -0.03, -0.01, 0.0}

Compute:
- N_suppressed (BUYs the rule would have blocked)
- N_kept_buys
- Kept_buys_hit_rate (suppression-adjusted accuracy)
- Suppressed_buys_hit_rate (what we ARE losing)

### Step 4: Statistical significance

For each (N, threshold) cell:
- McNemar test comparing baseline vs suppressed predictions
- Bootstrap confidence interval on hit_rate improvement
- Only accept rule if 95% CI excludes zero AND lift > 2pp

### Step 5: Out-of-sample check

Split data 70/30 chronologically. Tune rule on first 70%, evaluate on last 30%. If rule's edge disappears OOS, it was overfit.

### Step 6: Decision tree

| Result | Action |
|---|---|
| Rule lifts hit_rate >2pp, OOS confirms, CI excludes 0 | Implement in production gate |
| Rule lifts in-sample but fails OOS | Reject, document |
| Rule shows no edge | Reject, document |
| Rule HURTS hit_rate | Reject (don't suppress) |

## Open questions

1. Should we test the rule per-horizon (h=1 vs h=3 vs h=5 might respond differently)?
   - Yes, recommend per-horizon analysis
2. Threshold for inst_signed_flow_5d — relative (percentile of distribution) or absolute (-0.05)?
   - Absolute first (cleaner), percentile as fallback
3. If rule lifts hit rate but reduces N_kept_buys significantly, does that matter?
   - Yes — fewer signals = less opportunity. Track total $ return, not just hit rate.
4. Should the rule apply only to high-confidence BUYs (prob_eff > 0.65) or all BUYs?
   - Start with all BUYs, then sub-segment if rule works
5. What about negative inst flow WITHOUT earnings? Could be a separate suppression rule. (Different research question, future work.)
